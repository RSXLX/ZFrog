# ZFrog 家园下线并入记忆空间产品方案

## 一、决策摘要

### 执行更新（`2026-03-22`）

该方案已完成落地：

1. “家园”一级入口与主文案已下线，主入口统一收敛为“记忆空间”。
2. 留言、礼物、照片、成就、布置、访客管理已经进入记忆空间主视图。
3. `/garden` 与 `/visit/:address` 已降级为兼容解析路由，只负责跳转到记忆空间。
4. AI 导航与好友访问链路默认落到记忆空间，不再拼接独立家园语义。

自 `2026-03-22` 起，ZFrog 在产品层做出如下收敛决策：

1. 不再保留“家园”作为独立一级产品概念。
2. “家园”承载的能力继续保留，但统一并入“记忆空间”。
3. 对用户暴露的核心心智从“我有一个家园”调整为“我有一个可访问、可见证、可布置的记忆空间”。
4. 旅行结果页不再是终点，而是进入记忆空间的生成入口。
5. 好友访问、留言、礼物、照片、成就、空间布置必须在合并后继续成立，不能因为下线“家园”而消失。

这次下线的对象是“独立概念和独立入口”，不是“社交能力和空间能力”。

---

## 二、为什么现在要做

当前产品存在三层重复：

1. 用户心智重复
   用户同时面对“家园”“旅行结果”“记忆空间”三个空间概念，但边界不清。
2. 入口重复
   导航、青蛙详情、好友访问、AI 导航都在把用户导向“家园”，而旅行完成后又导向“记忆空间”。
3. 能力归属重复
   装饰、留言、礼物、照片、成就、访问关系分别挂在 `garden / homestead / memory-palace` 语义下，收敛方向与产品目标不一致。

如果继续保留“家园”和“记忆空间”并行，会带来三个后果：

1. 主体验不够聚焦，用户不知道“应该回哪里”。
2. 社交回访和旅行沉淀无法合并成一条完整叙事。
3. 工程侧会持续为两个相似概念维护入口、状态和接口。

---

## 三、产品目标

本次合并的目标不是让页面变少，而是让主叙事变清晰。

目标态应满足：

1. 用户只有一个空间概念可记忆。
2. 日常回访、旅行沉淀、好友访问都落在同一空间上。
3. 这个空间既能承接“今天的状态”，也能承接“过去的记忆”。
4. 空间既是情感资产，也是社交资产。

对应的一句话定义：

**记忆空间 = 青蛙当前生活状态、旅行沉淀内容、好友见证关系的统一容器。**

---

## 四、下线与保留范围

### 4.1 需要下线的部分

1. 顶部导航中的“家园”一级入口。
2. 青蛙详情页中“进入家园”的独立按钮文案与心智。
3. 好友列表、浮窗、AI 导航中的“访问家园”表达。
4. 把“家园”当作独立玩法模块的产品叙事。

### 4.2 需要保留并合并的部分

1. 空间展示
   青蛙、状态、装饰、照片、纪念品。
2. 社交承接
   好友访问、留言、足迹、礼物、互动。
3. 内容沉淀
   旅行 recap、时间线、纪念品、亮点、见证关系。
4. 陈列与成长
   成就展示、照片展示、空间布置、舒适度或空间等级。
5. 行动入口
   发起结伴旅行、查看关系状态、进入详情。

### 4.3 暂不下线的部分

1. 兼容路由
   `/garden` 与 `/visit/:address` 在过渡期继续保留，但作为兼容入口而不是主入口。
2. 内部技术命名
   允许短期内继续保留 `garden`、`homestead` 作为内部模块名，避免一次性技术重写。

## 五、目标信息架构

### 5.1 一级结构

产品一级结构收敛为：

1. 首页
2. 青蛙
3. 旅行日记
4. 纪念品
5. 徽章
6. 好友

“家园”不再作为一级导航存在。

### 5.2 空间主入口

记忆空间成为以下场景的统一落点：

1. 青蛙详情页的“空间”入口。
2. 旅行结果页的“进入记忆空间”入口。
3. 好友访问入口。
4. AI 导航中的空间类回答。

### 5.3 目标页面结构

记忆空间页至少应包含以下一级内容区域：

1. 空间概览
   展示青蛙、当前状态、空间视觉、纪念物摘要。
2. 回忆与时间线
   展示旅行 recap、高光、时间线、重要里程碑。
3. 见证与互动
   展示留言、足迹、来访记录、礼物。
4. 陈列与布置
   展示照片、成就、装饰，并支持主人编辑。

“记忆空间”不是只读回顾页，而是“可访问的活体空间”。

## 六、关键用户路径重构

### 6.1 主人日常回访

旧路径：

1. 进入青蛙详情
2. 点“家园”
3. 在家园里看留言、礼物、装饰

新路径：

1. 进入青蛙详情
2. 点“空间”
3. 在记忆空间里看当前状态、留言、礼物、陈列和最近回忆

### 6.2 旅行完成

旧路径：

1. 完成旅行
2. 查看结果页
3. 可选进入记忆空间

新路径：

1. 完成旅行
2. 查看结果页中的 recap
3. 自然进入该青蛙的记忆空间
4. 在空间里继续承接社交回访和见证

### 6.3 好友访问

旧路径：

1. 在好友页点“访问家园”
2. 进入对方家园
3. 留言或互动

新路径：

1. 在好友页点“访问空间”
2. 进入对方记忆空间
3. 在见证与互动区留言、送礼、留下访问痕迹

### 6.4 主人布置空间

旧路径：

1. 进入家园
2. 进入编辑模式
3. 拖拽布置装饰

新路径：

1. 进入记忆空间
2. 在陈列与布置区进入编辑模式
3. 拖拽布置装饰，并使布置结果成为空间长期陈列的一部分

## 七、分阶段落地策略

### Phase 0：冻结扩散

目标：

1. 停止新增任何“只属于家园、不属于记忆空间”的新功能。
2. 后续社交与空间类需求一律写入“记忆空间”语义。

### Phase 1：先合并文案与入口

目标：

1. 顶部导航移除“家园”。
2. 青蛙详情按钮从“家园”改为“空间”或“记忆空间”。
3. 好友访问文案从“访问家园”改为“访问空间”。
4. AI 导航从 `/garden` 转为记忆空间主入口。

这一步优先解决心智分裂，不要求一次性搬完所有能力。

### Phase 2：再合并能力容器

目标：

1. 留言、礼物、照片、成就统一出现在记忆空间页。
2. 空间布置能力迁入记忆空间的陈列区。
3. 好友访问默认进入记忆空间，而不是独立家园壳。

### Phase 3：最后下线独立家园

目标：

1. `/garden` 不再作为主导航目的地。
2. `/visit/:address` 只作为兼容跳转存在。
3. 所有产品文案中不再把“家园”作为独立功能名。

---

## 八、产品验收标准

### 8.1 体验验收

1. 用户不需要理解“家园”和“记忆空间”的区别。
2. 用户可以在一个空间中完成回顾、访问、互动、陈列四类操作。
3. 旅行完成后，用户自然知道下一步是进入记忆空间，而不是回到另一个页面体系。

### 8.2 功能验收

1. 原家园中的留言、礼物、照片、成就、装饰编辑能力在合并后仍然可用。
2. 好友访问链路在合并后仍然成立。
3. AI 导航、好友卡片、详情页 CTA 都不再把用户引向一个独立“家园”概念。

### 8.3 指标验收

至少观测以下指标在切换后不出现明显下滑：

1. 空间访问率
2. 留言发送率
3. 礼物打开率
4. 旅行完成后的记忆空间进入率
5. 好友访问转化率

---

## 九、风险与约束

### 9.1 主要风险

1. 记忆空间过于“静态回顾页”，导致日常活跃感下降。
2. 装饰编辑入口被埋，导致空间布置行为下降。
3. 老用户找不到“家园”，出现短期认知断层。

### 9.2 对应策略

1. 记忆空间必须保留实时互动和可编辑能力，不能只保留 recap。
2. 编辑入口要保留在空间主视图中，而不是藏到二级菜单深处。
3. 兼容期结束后，解释性文案可收缩，兼容路由仅保留跳转职责。

---

## 十、明确不做的事

本轮不做：

1. 一次性删除所有 `garden/homestead` 技术实现。
2. 在没有承接留言、礼物、访问能力前强制移除家园页面。
3. 把记忆空间重新做成只读 CMS 页面。

本轮真正要做的是：

**先完成产品心智与入口收敛，再推动能力和技术实现逐步并轨。**
